# DeskPet 隐私说明

**版本**: 0.6.0-beta
**更新日期**: 2026-05-22

> **一句话总结**：DeskPet 是一个纯本地应用。你的对话、API key、所有数据都只存在
> 你自己的电脑上，DeskPet 本体**不会主动联网上传任何东西**。唯一的对外网络请求，
> 是你自己配置的那个大模型 API（你填的 base_url）——那是你选择的服务商，不是我们。

这份说明逐条核对过代码实际行为，写的就是程序真正在做的事。

---

## 1. 你的数据存在哪

DeskPet 的所有用户数据都存在**本地磁盘**，不存在我们的服务器（我们没有服务器）。

具体位置取决于安装方式：

- **便携模式（MSI 安装的默认情况）**：数据存在**安装目录下的 `userdata/` 文件夹**里，
  例如 `C:\Program Files\DeskPet\userdata\`，和程序本体放在一起。这样设计的好处是
  C 盘不会被塞满，整个安装连数据一起拷到另一个盘也能直接用。
- **经典模式**：数据存在 `%AppData%\deskpet\`（即 `C:\Users\你\AppData\Roaming\deskpet\`）。

无论哪种模式，下面这些东西都在这个数据目录里：

| 数据 | 文件 / 目录 | 内容 |
|---|---|---|
| 完整对话历史 | `data/state.db`、`data/memory.db` | 你和桌宠说过的每一句话 |
| 配置 | `config.toml`、`llm_runtime.json` | 你的设置（base_url / 模型名等） |
| 日志 | `logs/` | 运行日志，用于排查问题 |
| 崩溃报告 | `crash_reports/` | 程序崩溃时的现场信息 |
| 使用计数 | `metrics.jsonl` | 匿名使用统计（详见第 5 节） |
| 模型 | `models/` | 本地 AI 模型文件 |

## 2. 对话历史（`state.db`）

你和桌宠的**完整对话历史**被保存在数据目录下的 SQLite 数据库
（`data/state.db` / `data/memory.db`）里。这是为了让桌宠能记住你们聊过什么、
能有「记忆」。

**这个数据库是纯本地的**——它从不被上传到任何地方。它只在两种情况下离开你的电脑：

1. 你自己手动去拷贝这个文件。
2. 你主动点了应用内的「反馈」按钮、并选择「附带诊断包」——但即便如此，诊断包里
   **也不包含 `state.db` 的完整内容**（诊断包只收集日志、崩溃报告、使用计数和
   一个脱敏的元信息文件，详见第 4 节）。

如果你想彻底清除对话历史，删掉数据目录下的 `data/` 文件夹即可。

---

## 3. API Key

你在设置里填的大模型 **API key 不会以明文写进任何配置文件**。

DeskPet 把 API key 存进 **Windows 凭据管理器**（Windows Credential Manager，
即操作系统自带的凭据库），存储项名为 `deskpet-cloud-llm`。这是 Windows 提供的
受保护存储区，和你保存的其他系统凭据一个待遇。

这意味着：

- API key **不在** `config.toml` 里，**不在** `llm_runtime.json` 里。
- 程序启动时从凭据库读出 key，注入给后端用于调用你配置的大模型——仅此而已。
- 诊断包**绝不会**读取或包含凭据库的内容（见第 4 节）。

> 如果你的旧版配置文件里残留了明文 api_key，DeskPet 在加载时会**忽略它并打一条
> 警告**，不会用它——请去设置里重新填一次，让 key 进入凭据库。

## 4. 崩溃报告与诊断反馈包

### 崩溃报告（自动、纯本地）

程序崩溃时（无论是前端 Tauri 层还是后端 Python 层），现场信息会被写入数据目录下的
`crash_reports/` 文件夹，文件名形如 `<时间戳>.txt`。

**崩溃报告只是落盘，不会自动发送给我们。** 它静静躺在你的电脑上，直到你主动
通过反馈功能把它发出来。

### 诊断反馈包（需要你主动触发）

应用内有一个「反馈」按钮。**只有当你主动点击它**、写下问题描述、并保留「附带
诊断包」勾选时，DeskPet 才会生成一个诊断 zip 包。这个包里有：

- `crash_reports/` 里的崩溃报告
- `logs/` 里最近几个日志文件
- `metrics.jsonl` 使用计数文件（见第 5 节）
- 一个 `meta.json` 元信息文件：应用版本、操作系统版本、数据库体积、内存占用、
  当前使用的大模型服务商名称和 base_url

**诊断包做了脱敏**，明确**不包含**：

- 你的 **API key**（`api_key` 等密钥字段会被主动删除）
- `llm_runtime.json` 这个文件本身（只保留脱敏后的服务商名 + base_url）
- Windows 凭据库的任何内容

而且——**生成诊断包不等于发送**。包生成后只是放在你电脑上，DeskPet **不会自动
上传它**。要不要把它发到内测群、发给我们，完全由你决定，是你手动操作的。

## 5. 使用计数（`metrics.jsonl`）

DeskPet 在数据目录下记录一个 `metrics.jsonl` 文件，里面是**匿名的使用计数**，
帮助我们在内测结束时回答「启动成功率多少、大模型调用成功率多少、哪个功能常用」。

它**只记录计数和分类**，比如：

- 应用启动成功 / 失败
- 大模型调用成功 / 失败（以及失败的错误类型，如「超时」）
- 某个技能（skill）被调用了
- 发生了一次崩溃

它**明确不包含**：

- 任何**对话内容**——你说过的话、桌宠的回复，一个字都不在里面
- 你的 **API key**

和崩溃报告一样，`metrics.jsonl` **只在本地落盘**。它只有在你**主动点「反馈」
并发送诊断包**时才会被一起带出去。如果你从不发反馈包，这个文件永远不会离开你的电脑。

---

## 6. DeskPet 会联网吗

**DeskPet 本体不主动联网上传任何数据。** 它会产生网络请求的情况只有：

1. **你配置的大模型 API**——你在设置里填的 `base_url`（比如某个云端大模型服务）。
   你和桌宠的对话内容会发给**这个你自己选择的服务商**，由它生成回复。这些内容
   在那个服务商那里如何被处理，取决于**那个服务商的隐私政策**，不在 DeskPet 的
   控制范围内。如果你在意这一点，可以配置一个本地大模型（如 Ollama），这样
   连对话都不出你的电脑。
2. **检查更新**——应用会向 GitHub 查询是否有新版本。这个请求只读取一个版本清单
   文件，不上传你的任何信息。
3. **首次启动下载模型**（如适用）——某些本地 AI 模型可能在首次启动时按需下载，
   这只是下载，不上传。

除此之外，没有遥测服务器、没有后台上报、没有「悄悄发数据回总部」这种事——
因为我们根本没有那个总部。

---

## 7. 如何清除你的数据

- **清除对话历史**：删除数据目录下的 `data/` 文件夹。
- **清除 API key**：在设置里点「清除」按钮，或在 Windows 凭据管理器里删除
  `deskpet-cloud-llm` 项。
- **彻底清除**：卸载 DeskPet 后删除整个数据目录（便携模式下即安装目录里的
  `userdata/` 文件夹）。注意：MSI 卸载默认**不会**删除你的数据目录——这是
  故意的，避免误删你的对话历史，但也意味着你需要手动删才算彻底清除。
