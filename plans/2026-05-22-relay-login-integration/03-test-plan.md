# 测试文档 — relay 登录 + 中转站充值接入

**关联**: `00-PRD.md` / `01-TDD.md` / `02-manual-test-cases.md`
**用途**: 整体测试策略、范围、环境、执行流程、退出标准。
**修订**: 第 2 版（2026-05-22）—— 随 M1-M6 修订。核心变化：后端测试范围
从"测新建热重载入口"收敛为"测 `update_cloud_config` 的 `persist_key`
旁路"；新增 key 轮换跨层重试闭环、bridge 失败可感知的验证点。

---

## 1. 测试目标

验证"内测付费版"接通后的端到端体验：**注册/登录 → 模型自动配好 →
开箱即用 → 余额不足可跳转充值**，且对 OSS manual 版**零回归**。

## 2. 测试范围

### 范围内

| 层 | 覆盖 |
|---|---|
| 构建 | `VITE_AUTH_EDITION` edition 切换（relay / manual / null）|
| 前端 | relayProviderBridge、onboarding relay 适配、充值链接、余额错误渲染 |
| 后端 | LLM endpoint 运行时热重载、`keys.py` relay 槽位解析、余额错误归一 |
| 集成 | 登录 → provider 推送 → 后端热重载 → 聊天/技能可用 |
| 端到端 | R1~R9 实机用例 |

### 范围外

- 中转站后端本身（注册/鉴权/计费）的正确性 —— 视为外部依赖，按
  `docs/中转站建议.md` 契约对接。
- 应用内支付（不做）。
- RelayAuthAdapter 的登录/注册/refresh 协议（已有，不在本次测试重点）。

## 4. 测试环境

| 项 | 要求 |
|---|---|
| OS | Windows 10/11，DPI 100% 或 150%（150% 需坐标换算）|
| 构建 | relay 构建（`build:relay`）+ manual 构建（对照）各一份 |
| 账号 | 中转站测试账号：A（有余额）、B（零余额或可 mock 402）|
| 网络 | 可访问中转站；另需可断网测离线分支 |
| 凭证 | 测试前清空 keyring 三槽位 + onboarding marker |
| mock | 无法造真实账号时：后端 mock LLM 402 验证余额链路 |

## 5. 执行流程

1. **自动化先行**：实现每个 WI 时先让对应 T 用例（T1-T6）转绿，再
   集成。
2. **回归门控**：每个 Sprint 结束跑 T7 三套全量，确认 0 回归。
3. **联调**：S2（后端热重载）+ S3（前端 bridge）联调，确认登录 →
   provider 推送 → 后端热重载链路通。
4. **端到端实机**：全部 WI 完成后，派 windows-mcp 子代理按
   `02-manual-test-cases.md` 跑 R1-R9，截图留证。
5. **修复循环**：子代理回报 bug → 修复 → 重跑 → 直到 Go。

## 6. 缺陷分级

| 级别 | 定义 | 处理 |
|---|---|---|
| P0 | R3（登录即用）或 R9（manual 回归）失败；凭证泄漏；key 明文落盘 | 阻断发版，立即修 |
| P1 | 余额链路 / 充值跳转 / 错误边界不符预期 | 发版前必修 |
| P2 | 文案、UI 细节、非关键提示 | 记录，可内测中迭代 |

## 7. 退出标准（测试通过 = 可进内测）

1. 自动化 T1-T6 全绿；T7 三套回归 **0 回归**。
2. 实机 R1-R9 全部通过，或仅环境受限未测且降级链路正确。
3. **R3、R9 两个一票否决项必须通过**。
4. P0 缺陷 = 0，P1 缺陷 = 0。
5. 安全核查：`llm_runtime.json` 全文无 `tsk_` 前缀（key 不明文落盘）；
   登出后三槽位确认清空。
6. PRD §7 DoD 全部满足。

## 8. 关键验证点（不可遗漏）

- ✅ relay 构建首启**强制登录**、**不出现手填模型步骤**。
- ✅ 登录后**零手填**即可聊天 + 触发办公技能（核心价值）。
- ✅ key 轮换后聊天不中断。
- ✅ `tsk_xxx` 只进 keyring，不进任何明文文件。
- ✅ 充值是**跳转链接**，不在应用内做支付。
- ✅ manual 构建行为与今日逐项一致（onboarding 三步 / Settings 手填）。
