## 4. Architecture proof — `_gate` + `_ctx` live in `AgentLoop`

Selected snippet from `backend/agent/agent_loop.py` (lines 448–499)
showing the construction-time wiring of both modules. Both default
to `None` when the flag is off, both auto-instantiate when the flag
is on, and both accept explicit injection (used by all P6 unit +
integration tests):

```python
# P6 Phase 3 — TerminationGate plumbing (feature-flagged).
#
# Three cases:
#   1. Caller injects an explicit gate → use it.
#   2. P6_ENABLE_GATE truthy → build a default gate with
#      max_turns = self.max_iterations.
#   3. Otherwise → self._gate = None (legacy path, unchanged
#      behaviour for the existing 1196-test baseline).
if termination_gate is not None:
    self._gate: Optional[TerminationGate] = termination_gate
else:
    try:
        from config import is_p6_gate_enabled as _flag_check
        _flag_on = _flag_check()
    except Exception:  # noqa: BLE001 — defensive: never break import
        _flag_on = False
    if _flag_on:
        self._gate = TerminationGate(
            GateConfig(max_turns=self.max_iterations)
        )
    else:
        self._gate = None

# P6 Phase 4 — ContextManager plumbing (feature-flagged).
#
# Mirrors the _gate logic above:
#   1. Caller injects ctx → use it.
#   2. P6_ENABLE_GATE truthy → build a default ContextManager.
#   3. Otherwise → self._ctx = None (legacy inline B1 path).
if context_manager is not None:
    self._ctx: Optional[ContextManager] = context_manager
else:
    try:
        from config import is_p6_gate_enabled as _flag_check_ctx
        _ctx_flag_on = _flag_check_ctx()
    except Exception:  # noqa: BLE001
        _ctx_flag_on = False
    if _ctx_flag_on:
        self._ctx = ContextManager()
    else:
        self._ctx = None
```

Per-iteration call sites (also in `run()`):

* `self._gate.allows_call()` — at top of each iteration (lines 579–589).
* `self._ctx.check_budget(working_messages, model=…)` — before LLM
  call (lines 613–642), short-circuits with
  `ErrorEvent(reason="context_budget_block")` on BLOCK.
* `self._gate.record_turn(cost_delta_usd=…)` — after each LLM call
  (lines 900–907).
* `self._gate.allows_tool(tc.name)` + `record_tool_call(tc.name)` —
  before each tool dispatch (lines 1102–1143).
* `self._ctx.record_tool_result(tool_name=…, result=…)` — after
  each tool dispatch, with `skip_truncation_for_tools` honouring the
  G1 fix (lines 1200–1203).
* `self._gate.record_final_answer()` — on `stop_reason='end_turn'`
  (lines 987–988).

## 5. Summary — what this proves

**The P6 refactor solves the two original observable bugs:**

1. **"Long task non-convergence"** — In the pre-P6 architecture a
   loop where the LLM kept calling tools could run to
   `max_iterations` (50) before the soft `_TOOL_BUDGET_HARD` system
   message convinced it to stop. With the gate, a budget of N forces
   the loop to terminate in N iterations regardless of what the LLM
   wants to do, AND the termination reason surfaces as the precise
   `error_tool_budget` enum — supervisors can diagnose immediately
   instead of guessing whether `error_max_turns` meant "user task is
   too big" vs "LLM got stuck in a tool loop".

2. **"G1 infinite fetch_tool_result loop"** — The pre-P6 code
   truncated every long tool result, including the fetch tool's own
   responses. So an LLM trying to retrieve a previously-truncated
   body got back another truncated body → fetched again → infinite
   loop. With `ContextManager.skip_truncation_for_tools`, fetch
   bodies pass through verbatim; we verified this end-to-end through
   the AgentLoop AND directly at the ContextManager contract.

**No flag-on regressions** were observed in the 1220-test legacy
baseline, which gives us confidence Phase 6 can flip the default to
on without breaking existing behaviour. If new
`error_tool_budget` / `error_wall_clock_exceeded` events start
appearing in production after Phase 6 ships, that's the gate working
as designed — they should be diagnosed individually (genuine task
too big vs threshold needs tuning) rather than treated as failures.
