## How we know break-out really cut iterations

Test `test_permanent_error_does_not_iterate_50_times` is the exact
falsifiable check: it pre-scripts **50 turns** of LLM responses and 50
broken tool envelopes. Before the fix, `AgentLoop` would consume all
50 (and then raise `max_iterations` error). After the fix, the
`_ScriptedLLM` stub raises `AssertionError` if it's called more than
the test allows, so any regression that re-introduces wasteful
iteration would fail loudly at test time instead of silently degrading
in production.

Concretely, the assertion is:

```python
assert llm.call_count <= 3, (
    f"loop iterated {llm.call_count} times — permanent break-out failed"
)
```

Observed `llm.call_count == 1` (single iteration before break).

## Concurrent-call edge case covered

`test_permanent_error_in_one_of_concurrent_calls_breaks` covers the
real-world shape where the LLM emits 2 `tool_calls` in one turn and
**one** of them returns the permanent error. The test asserts:

- both `ToolResultEvent`s are still yielded (downstream persistence
  needs them, supervisor needs them for diagnosis),
- but the loop does NOT proceed to a second LLM iteration — proving
  break-out happens *after* `tool_result` event emission, not before
  (which would have lost the events).

## Distinct hallucination reason

`test_hallucination_breaks_loop_with_distinct_reason` confirms a
`tool_not_found` error produces `ErrorEvent(reason="hallucination")`,
NOT `reason="permanent_tool_error"`. This is intentional — Phase 4
(AutoResume Orchestrator) will route hallucinations to the supervisor
for diagnosis rather than naive retry, while permanent errors get a
direct user-visible "工具用法错误" toast.

## Conclusion

- ✅ Permanent error → loop breaks at iteration 1 with reason
  `"permanent_tool_error"`.
- ✅ Hallucination error → loop breaks with distinct reason
  `"hallucination"` so Phase 4 routing can differentiate.
- ✅ Transient error → loop continues normally (no false-positive break).
- ✅ Concurrent calls — every `tool_result` event still yielded before
  break.
- ✅ No regression in completion-guard (Hook A) or base agent loop
  tests (26/26 pass).
- ⏳ Live E2E (real vpn-tunnel reproduction) deferred to phase-end
  integration, per task 2.11 acceptance gate. The unit tests above
  provide a falsifiable contract that any future regression would
  trigger immediately.

## Followup

- When Phase 4 (AutoResume Orchestrator) lands, the `ErrorEvent` with
  `reason="permanent_tool_error"` becomes the trigger that hands
  control to the supervisor. The detail field is already populated
  with the Phase-0 `hint` (when present) or `error` so the supervisor
  has actionable context.
- The `_extract_break_detail` helper in `agent_loop.py` prefers `hint`
  over `error` so a Phase-0-compliant tool gives the user remediation
  guidance, not just the raw failure string.
