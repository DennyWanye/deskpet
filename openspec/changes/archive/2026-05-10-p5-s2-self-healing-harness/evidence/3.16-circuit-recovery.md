## What was built

### Circuit breaker (`backend/agent/circuit_breaker.py` — NEW, ~155 lines)

Three-state machine keyed by `(session_id, tool_name)`:

```
CLOSED      ── 3 consecutive failures ──▶  OPEN
OPEN        ── cooldown elapsed       ──▶  HALF_OPEN  (allows ONE probe)
HALF_OPEN   ── probe success          ──▶  CLOSED
HALF_OPEN   ── probe failure          ──▶  OPEN  (cooldown timer resets)
```

- Time injected via `clock=` callable so unit tests don't sleep.
- `asyncio.Lock` around every transition (dispatch and watchdog touch from different tasks).
- Per-(sid, tool) isolation: opening `(sA, write_file)` doesn't affect `(sA, run_shell)` or `(sB, write_file)`.

### Dispatch integration (`backend/deskpet/tools/registry.py` — MODIFIED)

`ToolRegistry.execute_tool`:

1. **Before handler runs**: if `self._breaker is not None`, calls `await self._breaker.can_call(sid, name)`. If False → returns synthetic envelope:
   ```json
   {
     "ok": false,
     "result": "{\"ok\": false, \"error\": \"circuit_open\", \"hint\": \"write_file 连续失败 3 次已熔断 (剩余 N 秒)。检查参数或换个工具。\", \"available_alternatives\": [\"edit_file\"]}",
     "error": "circuit_open"
   }
   ```
   `available_alternatives` lists sibling tools in the same `toolset` (e.g. `write_file` → suggests `edit_file`), excluding the failing tool itself and cross-toolset tools.

2. **After handler runs**: records outcome to breaker via `await self._breaker.record_call(sid, name, ok=...)`. The "ok" determination handles three layers:
   - Handler raised → `ok=False` (caught by existing `except Exception`).
   - Handler returned non-JSON / serialization fail → `ok=False`.
   - Handler returned valid JSON envelope with `{"ok": false, ...}` (Phase 0 sensor pattern) → `ok=False`. Otherwise `ok=True`.

The new helper `_envelope_indicates_success(handler_result_str)` does the JSON parse + `ok` field inspection. Defensive: anything that doesn't parse as JSON / isn't a dict / has no `ok` field defaults to True (preserves backward compat for handlers that pre-date Phase 0).

### Same-signature repeat detection (`backend/agent/agent_loop.py` — MODIFIED)

- New optional kwarg `activity_store` on `AgentLoop.__init__` — when set, the loop reuses P5-S1's `SessionActivity.tool_signature_window` to detect repeats.
- Module constant `_REPEAT_NUDGE_MSG` (Chinese, with `{name}` and `{count}` placeholders) so other code can reformat / surface the same text.
- Module constant `_REPEAT_THRESHOLD = 3`.
- Detection point: between `AssistantMessageEvent` yield and the dispatch loop. For each `tool_call` in the response, looks up `f"{name}:{args_hash(args)}"` in the activity store; if `prior >= _REPEAT_THRESHOLD - 1` (i.e. this incoming call would be the 3rd identical), the loop:
  - Appends the assistant `content` (so the LLM sees its own prior message) + a `role=system` message containing the formatted nudge,
  - Logs `p5s2_signature_repeat_nudge`,
  - **Skips dispatch entirely** and `continue`s to the next iteration.

The next LLM call sees the nudge and can change tactics. No `ToolCallEvent` is emitted for the suppressed call (it didn't happen from the dispatch layer's perspective).
