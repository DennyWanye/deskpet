## hint 真能让 LLM 自纠的 e2e 思路（lead agent 验证用）

不在本 worktree 真启 deskpet（按 instructions 要求 lead agent 之后做），
但 LLM-self-correction 路径应该这样跑：

1. 启 deskpet code mode（`npm run tauri:dev` 全套）
2. 给一条故意诱导 LLM 漏 path 的 prompt：
   *"用 write_file 创建内容 hello"*（**故意没说文件名**）
3. **第 1 次工具调用**：LLM 大概率发出
   `write_file({"content": "hello"})`（漏 path）
4. **观察 tool_result**（应该是 Phase 0 新加的信封）：
   ```json
   {
     "ok": false,
     "error": "path required",
     "hint": "write_file 的 path 字段必填，且必须是非空字符串。例如 {\"path\": \"./hello.txt\", \"content\": \"hi\"}。",
     "examples": [
       {"path": "./notes/today.md", "content": "# Today\n- ..."},
       {"path": "main.go", "content": "package main\n"},
       {"path": "existing.txt", "content": "new", "overwrite": true}
     ]
   }
   ```
5. **第 2 次 LLM 应答**：因为 hint 直接给了示例 path，正常 LLM 会
   立刻补上一个合理 path（`./hello.txt` 之类）并重发 — 完成自纠循环
6. 比对 Phase 0 之前的旧行为：旧的 tool_result 只有
   `{"error": "path required"}`，LLM 经常会反复尝试不同猜测、最终 50
   iteration 用尽 max_iterations 才停 — 这正是 Phase 2 / Phase 3 / Phase 4
   要在更上层补的"防呆兜底"，但 Phase 0 这一层就能挡 80% 循环。
