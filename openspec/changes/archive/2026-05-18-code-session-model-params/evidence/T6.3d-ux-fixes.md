# T6.3d — three UX fixes (2026-05-19)

User follow-ups, all verified on the running app:

## 1. Context window is per-model & read-only (was fake 300K/1M)

"难道所有模型都支持 300K 和 1M 吗？" — no. The 300K/1M segmented was
the same mock-data problem. Now:
- `llm/model_catalog.py` `model_context_window(id)` — real nominal
  window by family, project `model_info` (BUILTIN + user TOML overrides)
  wins; genuinely unknown → `None`. `build_catalog` carries
  `context_window` per model.
- Picker shows a **read-only chip** "上下文窗口（模型决定）", not a
  selectable control. `context` is no longer sent as a param.
- Verified live: gpt-5.5 → **400,000 tokens (≈400K)**;
  claude-opus-4.5 → **200,000 tokens (≈200K)**; unknown →
  "由 provider 决定".

## 2. Model chip is clickable → opens the editor

"我希望点击图片中的按钮就可以编辑模型的细节." The model badge is now a
button (`gpt-5.5 ✎` / `默认模型 ✎`, shown even when unbound so it's
discoverable). Verified live: clicking it opens 模型与参数.

## 3. Provider dropdown = real provider names, provider-only

"下拉框就只是选择提供商，名字应该是 Settings 里 LLM Providers 的名字
（chinzy）." 
- Removed the `✏️ 改 model...` sentinel from the dropdown (model
  editing now lives on the chip).
- `ws.ts` now requests `settings_providers_list_request` on connect so
  the code panel actually has the provider list.
- The unpinned option is labelled with the real chain-head provider
  name from Settings (`chinzy（默认）`) instead of "Global Chain";
  generic label only when no providers are loaded.
- Verified live: both session cards show `provider: chinzy（默认）`.
