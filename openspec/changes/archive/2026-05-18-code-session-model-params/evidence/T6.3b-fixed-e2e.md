# T6.3b — CORRECTED real E2E + follow-up fixes (2026-05-19)

## Why this file exists

The original `T6.3-e2e.md` claimed PASS but its "proof" was a python
script that *re-ran* `resolve_provider_for_session` in isolation — that
only shows the function is self-consistent, not that the running app
uses it. The user did the real test (asked a code session its model;
it said `deepseek-v4-pro`) and was right to call it out. This file is
the real verification, on the running stack, plus the fixes the
investigation surfaced.

## Root cause of "it says deepseek-v4-pro"

The backend was, in fact, calling gpt-5.5 correctly. New instrumentation
(`openai_compat_outbound` in `providers/openai_compatible.py`,
`p5s2_chain_resolved` in `main.py`) proved the **actual outbound the relay
request** for the bound code session:

```
p5s2_chain_resolved sid='code-rkjdd9vo' in_code_mode=True
  code_default_model='gpt-5.5' n_entries=1 models=['gpt-5.5']
  code_params=[{'reasoning_effort':'high','extra_body':{'context_window':1000000}}]
openai_compat_outbound fn=chat_stream_with_tools model='gpt-5.5'
  reasoning_effort='high' extra_body={'context_window':1000000}
```

The session *said* "deepseek-v4-pro" because
`deskpet/agent/assembler/components/persona.py` formats the persona
system prompt with the model from the **static `[llm]` config**
(`getattr(local_llm,"model")` in `main.py`), not the per-session
resolved model. So a gpt-5.5 session truthfully read a wrong prompt.

## Fixes applied (this commit)

1. **Persona reports the resolved model** — `main.py` assembler config
   now resolves the code session's model (binding `preferred_model` →
   `[agent].code_model` → legacy) and passes THAT to PersonaComponent.
2. **Live model catalog, no mock data** — `llm/model_catalog.py`:
   `fetch_models` pulls the relay `GET /models`; fallback to the registry
   endpoint's configured `models`; `model_param_caps` is a per-family
   capability map. New `code_models_list` ws handler. Hardcoded
   `CODE_MODEL_PRESETS`/`buildModelOptions`/`buildModelParams` deleted.
3. **Per-model param differentiation** — picker is caps-aware:
   gpt-5.x → Effort+Fast+Thinking+Context; claude opus/sonnet →
   Thinking+Context only (no Effort, no Fast); embeddings → none.
4. **Binding survives restart** — `code_sessions_list_response` now
   carries `provider_id/preferred_model/model_params`, so the tile's
   model badge + picker pre-fill no longer vanish on reconnect.
