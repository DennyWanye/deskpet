## 1. 场景 (Scenarios covered)

This phase implements `backend/llm/provider_registry.py` exposing:

- `LLMProviderRegistry` — owns the in-memory provider list, persists `[[llm.providers]]` to `config.toml`, manages OS-keychain api_keys.
- `ProviderEntry` — dataclass (`id`, `name`, `base_url`, `model`, `api_key_ref`, `priority`, `enabled`); intentionally does NOT store the api_key on the dataclass so accidental `asdict()` / log dumps cannot leak.
- `NoProviderConfiguredError` — actionable error raised by `get_chain()` when zero enabled providers exist.
- `_migrate_legacy_provider_config()` — startup migration from legacy `[llm.local]` single-provider schema → new `[[llm.providers]]` array.

## 4. 实现要点 (Implementation notes)

- **Atomic toml writes**: `_atomic_write_text()` writes to `path.tmp`, then `os.replace(tmp, path)` — same pattern as `backend/llm/budget.py`. No crash can leave the file half-written.
- **No `tomli_w` dependency**: the project doesn't ship `tomli_w` (verified via `python -c "import tomli_w"`). Instead `_format_providers_section()` hand-writes the `[[llm.providers]]` blocks, and `_strip_existing_providers_block()` removes old blocks line-by-line so all non-providers content (comments, other tables) is preserved verbatim.
- **Keychain abstraction**: `keyring` import is wrapped in try/except (mirrors `backend/llm/keys.py`); accounts use `provider.<id>` under service `"deskpet"`. The `api_key_ref` string in toml is `deskpet.provider.<id>` and is the only secret-shaped field shown publicly.
- **Migration `api_key_ref`**: matches design.md scenario — the legacy `deskpet.cloud_api_key` keychain entry is referenced verbatim (`LEGACY_CLOUD_KEYCHAIN_REF`), NOT moved. Users don't have to re-enter their existing chinzy/cloud key.
- **No `main.py` changes**: per Hard Rule #3, `_migrate_legacy_provider_config()` exists as a free function in `provider_registry.py` ready for Phase 2/3 to wire into `main.py` lifespan. Phase 1 only unit-tests it in isolation.
- **Async mutators**: `add_provider` / `remove_provider` / `set_enabled` / `reorder` / `update_provider` are `async def` so Phase 2's IPC layer can `await` them and broadcast `providers_changed` without a signature change.
