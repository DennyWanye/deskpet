## Design notes / deviations

- **Error envelope** — all validation failures share a single
  `settings_providers_error { reason, detail }` shape. `reason` is one
  of: `duplicate_id`, `missing_field`, `invalid_id`, `invalid_payload`,
  `not_found`, `incomplete_order`, `registry_unavailable`,
  `internal_error`. Frontend (Phase 4) discriminates via `reason` only;
  `detail` is for UX strings.

- **Broadcast pattern** — `providers_changed` fans out to every entry
  in `_control_connections` (the module-level `dict[sid, WebSocket]`
  also used by `_todo_broadcaster` and the supervisor alert broadcaster).
  The sender ws ALSO receives it (in addition to its targeted
  `*_added/_updated/_removed/_reordered` response) — frontend stores
  treat both as "new state arrived" idempotently.

- **`code_session_set_*` always reads-then-writes** the existing binding
  row so the response carries both fields. `code_session_set_provider`
  preserves the prior `preferred_model`, and vice versa. If both fields
  end up `None`, `SessionDB.set_code_session_provider_binding` deletes
  the row (semantics from Phase 0).

- **Keychain isolation in tests** — `fresh_registry` monkey-patches
  `llm.provider_registry.keyring` to an in-memory dict so neither the
  Windows Credential Manager nor the macOS Keychain is touched.
