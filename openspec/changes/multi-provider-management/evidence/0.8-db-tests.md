# Evidence — Phase 0: SessionDB migration + 数据层

## 场景

实现 OpenSpec change `multi-provider-management` 的 Phase 0：

- **capability `code-session-provider-binding`** 在 SessionDB 落地：
  - 新表 `code_session_provider (base_session_id PK, provider_id TEXT, preferred_model TEXT, updated_at REAL)`
  - schema `user_version` 从 10 升到 14
  - `SessionDB.get_code_session_provider_binding(sid)` / `set_code_session_provider_binding(sid, provider_id, preferred_model)` 两个 async 方法
  - 全 None 调用 set → 删行，符合 spec "Clear override" scenario

## 操作步骤

1. 在 `backend/deskpet/memory/migrations/` 下新建 `006_p5s2_code_session_provider.sql`，建表 + `PRAGMA user_version = 14`。
2. 在 `backend/deskpet/memory/migrator.py` 把 `TARGET_SCHEMA_VERSION` 从 10 升到 14。
3. 在 `backend/deskpet/memory/session_db.py` 加 `get_code_session_provider_binding` 与 `set_code_session_provider_binding`（async，aiosqlite + write_lock + retry 包装，UPSERT 用 SQLite `ON CONFLICT`）。
4. 在 `backend/tests/test_p5s2_code_session_provider_db.py` 写 6 个测试覆盖 spec scenarios + migration 幂等 + v13→v14 升级保留旧数据。
5. 修两条旧 migrator 测试，把硬编码的 `user_version == 10` / `count == 2` 改成 `== 14` / `== 3`（schema 合法演进）。
6. 跑：
   - `cd backend && python -m pytest tests/test_p5s2_code_session_provider_db.py -v`
   - `cd backend && python -m pytest tests/ -q --ignore=tests/test_deskpet_vector_worker.py`
