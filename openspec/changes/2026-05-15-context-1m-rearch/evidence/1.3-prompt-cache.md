# Evidence: 1.3 prompt-cache (4-breakpoint prompt cache + 前缀稳定纪律)

**When**: 2026-05-15 16:46:56 UTC+8
**Who**: subagent (Phase 1.3, OpenSpec 2026-05-15-context-1m-rearch)
**What we tested**: OpenAI-compat（the relay / deepseek-v4-pro）prefix-cache
前缀稳定纪律 + cached_tokens 命中率埋点的单测层验证。真 E2E（连续 5 轮
对话 cache 命中率 ≥50% + 截图）由 lead agent 做（task 1.3.5）。

## 范围与决策

design.md **D4**：OpenAI-compat 走 prefix cache，命中条件不是"打什么
标记"，而是"history 字节前缀跨轮稳定"。所以 Phase 1.3 在 provider 层
（`backend/providers/openai_compatible.py`，唯一允许改的 production 文件）
做三件事：

| task | 做法 |
|---|---|
| 1.3.1 固定 messages 装配顺序单测 | 纯函数 `_cache_breakpoint_order(messages, has_tools)` 给出 [system, tools, memory, history, last-user-pre] 逻辑断点契约序。实际装配在上游 ContextAssembler/chat handler；provider 在边界给契约让单测断言"易变块没被插进前缀"。 |
| 1.3.2 前缀稳定纪律 | 纯函数 `_stabilize_prefix(messages)` 返回副本：tool-call-only assistant 的 `content` 缺失/None → 稳定 `""` placeholder；空/None `reasoning_content` → 一律删 key（不让"空 key" vs "无 key" 抖动字节哈希）。在 `chat_stream_with_tools` 与 `_legacy_chat_with_tools_nonstream` 装 payload 前调用，作用在出站 messages 上（AROUND pitfall #7 的 SSE 双编码 parser，**未改动**那段 load-bearing 代码）。 |
| 1.3.3 Anthropic `cache_control` | **N/A — 已实现，无新增工作。** 详见下节。 |
| 1.3.4 cache 命中率日志 | `_extract_cached_tokens(usage)` 防御式取 `usage.prompt_tokens_details.cached_tokens`（OpenAI/deepseek 标准）或 `usage.cached_tokens`（部分中转站平铺）；缺失/脏数据 → `None`。`_log_cache_hit_rate` 落 `p4s25_prompt_cache_hit` 日志，字段缺失记 `cached_tokens=unknown`，绝不崩。stream 路径 + 非流路径 final 点各埋一处。 |
| 1.3.5 真 E2E | 不在本 subagent 范围，lead agent 做。 |
